# Архитектура

## Обзор

Mind MCP Server построен на слоистой архитектуре с чётким разделением ответственности. Сервер работает через stdio-транспорт и предназначен для запуска MCP-клиентом.

```
MCP-клиент (Claude Desktop / Claude Code)
    ↕ stdio (JSON-RPC)
┌─────────────────────────┐
│  index.ts                │  ← Точка входа, регистрация инструментов
├─────────────────────────┤
│  tools/*                 │  ← Обработчики MCP-инструментов
├─────────────────────────┤
│  api/client.ts           │  ← HTTP-клиент для Mind API
├─────────────────────────┤
│  types.ts                │  ← Общие TypeScript-типы
└─────────────────────────┘
         ↕ HTTP (fetch)
      Mind API (NestJS)
```

## Структура проекта

```
src/
├── index.ts              # Создание McpServer, регистрация инструментов, запуск stdio
├── types.ts              # TimeOfDay, BreathSession, BreathStep и др.
├── api/
│   └── client.ts         # fetchSessions, fetchSession, patchSession
└── tools/
    ├── listSessions.ts   # list_my_breath_sessions
    ├── classifySession.ts# classify_session_time_of_day
    ├── setTimeOfDay.ts   # set_session_time_of_day
    └── classifyAll.ts    # classify_all_sessions
```

## Правила зависимостей

| Модуль | Может импортировать |
|--------|---------------------|
| `index.ts` | `tools/*` |
| `tools/*` | `api/client`, `types` |
| `api/client.ts` | `types` |
| `types.ts` | ничего (leaf) |

Циклические зависимости запрещены.

## Потоки данных

### Запрос от AI-ассистента

1. MCP-клиент отправляет JSON-RPC запрос через stdin
2. MCP SDK маршрутизирует запрос к зарегистрированному обработчику в `tools/`
3. Обработчик вызывает функции из `api/client.ts`
4. API-клиент выполняет HTTP-запрос к Mind API с Bearer-токеном
5. Результат форматируется в MCP-формат (`content[]` с `type: "text"`) и возвращается

### Обработка ошибок

Ошибки API перехватываются на уровне инструмента и возвращаются как результат с `isError: true`. Исключения никогда не пробрасываются выше обработчика — это требование MCP-протокола.

## Ключевые принципы

- **Один файл — один инструмент.** Каждый MCP-инструмент живёт в отдельном файле в `tools/`
- **API-клиент — единственная HTTP-граница.** Инструменты не делают fetch напрямую
- **stdout зарезервирован** для MCP-протокола. Логи — только в stderr
- **Конфигурация из окружения.** Никаких файлов конфигурации, только env-переменные
- **Нет shared state.** Каждый вызов инструмента — независимая операция

## Зависимости

| Пакет | Назначение |
|-------|-----------|
| `@modelcontextprotocol/sdk` | MCP-протокол: сервер, транспорт, типы |
| `zod` | Валидация входных параметров инструментов |

Для HTTP-запросов используется встроенный `fetch` (Node.js ≥ 18).
